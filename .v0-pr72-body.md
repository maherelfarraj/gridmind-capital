The **Administrators** tile on `/admin/users` displayed the hardcoded string `"Tenant + 2 PMO"`.

It was wrong three ways:

- Production has **2 tenant_admins and 0 system_admins** — verified read-only.
- There is **no "PMO" role** in the system. `DB_ROLE_META` has no such entry.
- Being a literal, it could never track the number rendered directly above it.

The count itself was correct, and **its logic is unchanged**.

## Fix

New `lib/admin/admin-summary.ts` derives the subtitle from real role counts:

```ts
formatAdministratorSummary({ tenant_admin: 2 })                  // '2 Tenant Admins'
formatAdministratorSummary({ tenant_admin: 2, system_admin: 1 }) // '2 Tenant Admins · 1 System Admin'
formatAdministratorSummary({})                                   // 'No administrators'
```

Zero-count categories are omitted, singular/plural is handled, and labels come from `DB_ROLE_META` so a role rename cannot leave a stale name behind.

## One review finding worth flagging

`DB_ADMIN_ROLES` — the set the tile already counts — is **three** roles, including `project_director`, not just the two admin roles.

Production has 0 directors today, which is exactly why the tile currently reads correctly *while still being unable to stay correct*: the moment a director existed it would have rendered **"3"** above **"2 Tenant Admins"** and looked like a fresh bug.

So directors are reported as their own category. The subtitle now sums to exactly the displayed total by construction — `totalAdministrators()` adds up the same counts the subtitle prints, so the two cannot drift apart.

I did not change what counts as an administrator.
