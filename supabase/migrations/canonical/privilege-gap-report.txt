READING NOTE -- EXPLICIT vs EFFECTIVE vs OWNER-DERIVED
  Every figure below comes from the stored ACL arrays, never from
  has_table_privilege()/information_schema effective views. Where production
  shows a `postgres` ACL entry on an object owned by postgres, that entry is
  the ordinary owner-default that PostgreSQL materialises into the ACL as soon
  as any GRANT is issued on the object. It is classified OWNER-DERIVED: it
  needs no statement in the baseline provided the baseline is executed as
  postgres. It is NOT evidence of a hand-written GRANT.

    that cannot be logged in as. Its ACL entries carry grantor=pg_database_owner.
    A migration running as postgres cannot produce that grantor. On a fresh
    Supabase project the schema already exists with this ownership, so the
    baseline should NOT create or re-own schema public; it should assume it.
    Whether postgres can even issue GRANT USAGE ON SCHEMA public depends on
    implicit pg_database_owner membership (true only if postgres owns the
    database). pg_auth_members does not record implicit membership, so this was
    NOT verifiable by introspection and must be confirmed at execution time.
  - supabase_admin-owned default ACLs (section 6, rows 4-6).

Everything else is owned by postgres and is reproduced implicitly by executing
the baseline as postgres. The draft's explicit ALTER … OWNER TO postgres for 28
functions and 6 views is harmless and self-documenting; ALTER OWNER for tables
and sequences is unnecessary for the same reason.

     current_user / session_user ................................ postgres

   The right test is pg_has_role(), or equivalently datdba = current_user.

   CONSEQUENCE: the 5 section-A0 schema USAGE grants ARE executable by the
   migration role. Section 8's "grantor only" owner-action note stands, and
   production's own nspacl already records grantor pg_database_owner on all five
   entries, which is consistent with grantor selection preferring the owner.

   CAVEAT KEPT: grantor provenance is EXPECTED, not proven. It cannot be
   observed without executing a grant, and no grant was executed.
