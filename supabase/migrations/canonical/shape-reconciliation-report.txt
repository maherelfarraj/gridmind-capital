AMENDMENT 1 -- SECTION 7.3 IS WRONG.
  Section 7.3 states the baseline "contains ZERO executable GRANT, REVOKE or
  ALTER DEFAULT PRIVILEGES statements across all six files". THAT IS FALSE.
  20260801000003_rls_policies_grants.sql already carried a grants block which
  granted anon, authenticated and service_role on every public table and view.
  Every GRANT in it was assembled dynamically as a string inside a DO block, so
  a scan anchored on a statement-initial GRANT/REVOKE keyword returned zero.

  This is the SIXTH regex/scanner false result in this reconciliation, and the
  only one that produced a false NEGATIVE rather than a false positive: it
  under-reported what the baseline contained instead of over-reporting drift.
  Scanners over SQL must account for dynamic SQL inside DO blocks and function
  bodies, not only statement-initial keywords.

  Section 7.3 also cited the README as corroboration ("Grants | present | none
  (dumped --no-acl) | all missing"). That row compares THE PG_DUMP to
  production, not the canonical baseline to production. The README was correct;
  this report misread it. That misreading is what made the gap look like a
  known, already-accepted limitation.

AMENDMENT 2 -- WHAT THE GRANTS REWRITE DOES AND DOES NOT COVER.

N1  Schema qualifier. `public.<enum>` in the draft == `<enum>` from
    format_type() under the live search_path. Applied to type names and to
    the `::type` casts inside DEFAULT expressions. 18 columns relied on this.
N2  Identity clause location. pg_dump emits identity as a separate
    `ALTER TABLE ... ADD GENERATED ... AS IDENTITY` statement rather than
    inline. The draft's 2 ALTER statements were folded into the owning column
    before comparison. Both are GENERATED ALWAYS, matching attidentity='a'.
N3  Whitespace. Runs of whitespace collapsed to a single space in function
    bodies, view definitions and policy expressions.
N4  Redundant outer parentheses. `USING ((expr))` in the draft vs pg_policies'
    rendering `(expr)`. Stripped only when the outer pair wrapped the entire
    expression. Grouping parens were NEVER stripped -- see section 7.
N5  Subselect display alias. pg_policies renders `(SELECT auth.uid())` as
    `( SELECT auth.uid() AS uid)`. The `AS uid` is a rendering artifact of the
    catalog view, not part of the stored expression.

Rules deliberately NOT applied: nothing was normalized for defaults, FK
actions, nullability, volatility, security attributes or role lists.
