Blocker 3 above ("on_auth_user_created remains commented out") is RESOLVED. The
reasoning that produced it was wrong, and the retraction is recorded rather than
edited away.

THE FALSE CLAIM
  "auth.users is owned by supabase_auth_admin, so the migration role cannot
   create a trigger on it."

WHY IT WAS WRONG
  CREATE TRIGGER requires the TRIGGER privilege on the target table plus EXECUTE
  on the trigger function. Table ownership is NOT a requirement. The blocker was
  inferred from an owner name rather than from a privilege check -- the object's
  owner was never the governing condition.
