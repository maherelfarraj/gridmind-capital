D7 -- THE FK FINGERPRINT ASSERTION HAD NEVER EXECUTED
--------------------------------------------------------------------------------
SQLSTATE:  42725
Message:   operator is not unique: text || "char"
Location:  20260801000005_postconditions.sql, FK fingerprint SELECT

ROOT CAUSE
  pg_constraint.confmatchtype, .confupdtype and .confdeltype are PostgreSQL's
  internal "char" type -- a 1-byte type distinct from char(1), bpchar and text.
  Several candidate || operators exist for text || "char" and none is an
  unambiguous best match, so the parser raises 42725.

  The error is raised at PARSE time inside the single DO block, so it aborted the
  whole file and nothing downstream ran. The FK fingerprint assertion --
  canonicalized in the previous pass and treated as authoritative -- had
  therefore NEVER executed even once.

CORRECTION (the entire fix: three casts)
  before:  ||'|'||co.confmatchtype||'|'||co.confupdtype||'|'||co.confdeltype
  after:   ||'|'||co.confmatchtype::text||'|'||co.confupdtype::text
           ||'|'||co.confdeltype::text

  Formula, field order, separators, sort order and expected hash are UNCHANGED.
  A cast changes operator resolution, not the rendered value -- confirmed by the
  hash reproducing the production value exactly.

--------------------------------------------------------------------------------
ROOT CAUSE
  The file opened with SET client_min_messages = warning, silencing NOTICE. Every
  diagnostic this suite emits is a RAISE NOTICE, so a passing run printed only
  BEGIN / SET / SET / DO / COMMIT. This is not cosmetic: no grant fingerprint was
  ever captured from production, so for the privilege dimension these emitted
  hashes are the ONLY output the design produces. Suppressed, a "successful" run

CORRECTION

  SET LOCAL client_min_messages = notice;
